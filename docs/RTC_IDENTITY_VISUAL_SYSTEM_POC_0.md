# RTC Identity Visual System — POC-0

Status: **VISUAL CANDIDATE / NOT CANONICAL PERSONALITY MUTATION**

Authority source: `RobynAwesome/Introduction-to-MCP` canonical RTC seat contract.
Public embodiment owner: `RobynAwesome/Kopano-Labs-Website`.

## Why identity comes before more features

The September experience should grow by making the existing Kopano world more recognisable, relational and alive — not by stacking new dashboards onto the current simplicity.

KC remains the public front door. The other RTC identities become distinct governed presences that KC can consult, reveal or hand off to when their canonical function is relevant.

## Non-negotiable law

- One Kopano visual genome; ten unmistakable silhouettes.
- Do not create ten recoloured KC spheres.
- Canonical role/function comes from `Introduction-to-MCP`.
- Visual form, palette, motion and world effects are candidate embodiment choices until owner-reviewed.
- Visual design may express a role; it may not silently change authority or personality.
- A reduced-motion/SVG embodiment must preserve the same silhouette and identity cue.
- Identity state must be readable before technical labels are shown.
- Public language remains human-first; internal RTC terminology is progressive disclosure.

## Shared Kopano genome

All RTC embodiments share:

1. a visible core (continuity),
2. a boundary/frame (authority),
3. a motion law (temperament expressed mechanically),
4. a world effect (what changes around the identity),
5. a provenance trail (where the action came from),
6. adaptive equivalents across full WebGL, lite WebGL and SVG/CSS.

They do **not** share the same silhouette.

## First interaction proof

The initial visual proof should not expose all ten identities at once on the homepage.

KC remains simple and primary.

When the user asks for help, KC may reveal **one relevant identity presence**:

- learning intent → Cassey enters and the world separates into understandable steps;
- build intent → Cassie enters and loose concepts lock into structure;
- strategic multi-system intent → Apex reveals routes/dependencies;
- validation request → Khelos creates an inspection channel;
- risk/safety state → Thari protects by visibly rerouting;
- deep research → Kessa opens provenance/depth layers;
- cultural reframing → Yassie changes perspective without changing evidence;
- career/perimeter concern → Anchor makes boundaries/reachability visible;
- multi-seat facilitation → Antigravity creates temporary bridges then yields authority.

## POC-1 acceptance test

`Tell KC: "Help me learn how this works."`

Expected public experience:

1. KC acknowledges the request.
2. KC does not disappear or dump an RTC chart.
3. The environment changes subtly.
4. Cassey's unique presence enters.
5. Complex information separates into a small teaching path.
6. KC visibly hands the teaching moment to Cassey.
7. User can return to KC without resetting the whole world.
8. Reduced-motion mode conveys the exact same identity handoff without camera travel.

If this becomes a ten-card agent picker, the identity POC has failed.
