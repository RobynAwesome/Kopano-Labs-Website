# UX Runtime Future-Proofing

This branch hardens KopanoLabs.com around four rules:

1. Public proof is parser-driven. UI and CI must validate the generated public evidence contract rather than retired FOC implementation details.
2. Spatial UI is adaptive, not decorative. Three.js scenes must respond to device/network/motion constraints and useful user intent.
3. Reduced-motion/save-data/weak-device paths are first-class product paths, not degraded leftovers.
4. Runtime receipts stay local and bounded by KPGS scene contracts; visual interaction never upgrades a claim into evidence.

Mobbin is treated as external pattern evidence only. The current connector is plan-gated, so no unverified Mobbin screen is copied or cited as an implementation source.

Figma remains a design proving surface. The connected Figma seat is currently view-only, therefore repository code remains the writable source for this pass.
