## 1. Authority order

Model confidence never outranks an existing governed artifact.

## 2. Artifact supremacy

Existing user code is presumed intentional.

- Code exists -> improve it; do not replace it.
- Design exists -> evolve it; do not redesign it by default.
- Route exists -> preserve it unless its removal is explicitly authorized.
- Asset exists -> inspect and reuse it before generating a substitute.
- Repository is specified -> do not substitute another repository.
- Premise is accepted -> execute downstream; do not reopen validation unless asked.
- Fix is requested -> mutate the responsible defect, then validate the mutation.
- Deploy is requested -> deploy the existing artifact lineage, not an invented replacement.

Replacement, redesign, refactor, deletion, or generation requires an explicit reason and must preserve fixed invariants recorded in `now.md`.

## 3. One Forge, many windows — concurrency law

Multiple ChatGPT windows may work on this estate, but no window may assume another window's latest mutation is already present in its context.

Personalized Intelligence / project memory is useful context, but it is not the transactional concurrency ledger for repository state.

The repository is the shared durable coordination surface.

Before every mutation:

1. fetch latest `main`
2. read `now.md`
3. re-read the target file at latest `main`
4. check whether another commit changed the target or its governing invariant
5. if state changed, rebase the intended action on the new state rather than restoring an older interpretation

After every completed mutation:

1. update the relevant checkbox/status in `now.md`
2. record the commit SHA or proof receipt
3. record any newly discovered blocker without deleting prior history
4. never mark complete without source/build/live evidence appropriate to the task

`now.md` is append-and-evolve coordination state. Do not casually erase completed history or pending work.

1. `KRRababalela.com` / `RobynAwesome/Portfolio-MBR` — interaction and visual DNA

## 5. Proof discipline

`OBSERVE -> READ AUTHORITY -> CLASSIFY -> MUTATE -> BUILD -> VALIDATE -> RECORD`

`OBSERVE -> EXPLAIN -> RE-EXPLAIN -> SUBSTITUTE -> CLAIM`
